# 长产物的构造方式

命中长产物判据后怎么做：三步做法、分区划法、完整示例。判据本身在 SKILL.md §长产物的构造方式，命中判定在步骤 2.6b。

进入步骤 2.6b 判定命中时，或实现阶段搭产物模板时读。

目录：

- §一 三步做法
- §二 分区怎么划
- §三 完整示例
- §四 反模式

## 一、三步做法

1. **程序建骨架**：由程序（不是 Agent）先落地产物文件，写全所有必填分区的标题、占位符、每区的字段说明与格式要求。模板即契约——该有什么内容，在模板里就已经定死。
2. **Agent 分区编辑**：Agent 用编辑工具逐区填充，**一轮只针对一个分区**，提示词里只给该区所需的上下文与规则。分区互不重叠时可并行填充（受 SKILL.md §并发与任务拆分 的四条约束）；有重叠或有先后依赖的串行。
3. **程序校验回流**：程序检查占位符是否残留、必填分区是否齐全、格式能否解析；不合格项**只把该分区退回重填**，不重做整份产物。校验由程序实现，**不以 Agent 自评替代程序校验**。

这样做换来五件事：不撞单次输出上限；每轮注意力只落在当前分区；产物结构化程度高、易校验；出错只需重填一个分区而非全文；模板预先框定内容，模型不易遗漏，漏了程序也会点名补。**注意力差、准确率低的模型收益最大**——它把"一次做对一整篇"降级成"一次做对一小块"。

## 二、分区怎么划

- **顺着产物自身的结构切**：章节、表格的行组、数据对象的顶层字段。不要为了凑数硬切。
- **每区能独立判断对错**：一个分区填得对不对，不需要读其他分区就能判定。判不了 → 说明切错了位置。
- **不重叠**：同一句结论不由两个分区各写一遍，否则并行填充会冲突、校验会互相打架。
- **依赖显式标顺序**：需要综合前面各区才能写的分区（总结、结论、目录），排在后面串行执行，并在分区表里标明依赖。
- **每区带字段说明**：占位符里写清本区要包含什么、格式是什么。只有标题没有说明的模板等于没框定内容。

分区表写进设计文档的「信息传递链路」一节，字段见 `design-doc-template.md` §二。

## 三、完整示例

任务：产出一份约 20 页的《竞品调研报告》。

1. **程序建骨架** `report.md`：8 个二级标题，每节留占位符——
   `<!-- FILL §3: 竞品定价对比。需含：3 家竞品 × 4 个套餐档位的价目表（markdown 表格）+ 一段不超过 200 字的差异说明。价格标注币种与生效日期。 -->`
2. **程序派发**：§1–§6 互不重叠，六个 Agent 并行填充（并发数受已确认上限约束）；§7 综合结论依赖前六节，排在其后串行；§8 附录由程序直接生成，不经 Agent。
3. **每个 Agent 的首轮提示词只给三样**：本区占位符说明、该区所需的原始数据、编辑工具与目标文件路径。不给整份报告的上下文，也不给其他分区的资料。
4. **程序校验**：grep 是否还有 `<!-- FILL` 残留；每节字数下限；表格列数是否符合声明；引用链接是否可达。发现 §3 的价目表缺币种 → **只把 §3 退回重填**，附上失败原因。
5. **结果**：单次输出上限从未成为约束；一次返工的成本是全文的 1/8，而不是重来一遍。

## 四、反模式

- 让 Agent 用一条消息 print 出整份长文档。
- 用 Agent 而不是程序做完整性校验（自检是好习惯，但不能当验收依据）。
- 模板只有标题、没有字段说明——Agent 只能猜该写什么，等于没框定内容。
- 分区切得比产物结构更碎，导致每区都要读别的区才能写。
