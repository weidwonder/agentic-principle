# 工具返回的体量控制

维度 D4。估工具返回体量时读；实现阶段做落盘兜底、写极端返回用例，或评审阶段核对返回体量时也读。

一次超长的工具返回能吃掉整轮上下文预算，而它的大小由**外部数据**决定——设计期看着没问题，上线撞上一个大仓库、一张大表、一个长日志就爆。这是上下文耗尽最常见的来源，且没有任何提示词纪律拦得住。

**检查范围**：返回**直接进入模型上下文**的工具与 MCP（自建的 + 引入的第三方）。Skill 内 CLI 与外部 CLI 通常不在此列——它们经 shell/bash 通道调用，由通道侧的统一截断/落盘兜底，CLI 自身提供 limit / 分页 / 摘要参数即可。**自建 agent loop 时，通道工具的兜底就是你的工程职责，必须实现**（见 `../runtime/agent-loop.md` §六）。

**红线**：单次返回 > 10k token（≈ 40KB 英文 / ≈ 1.5 万汉字）视为超长，必须有处置。**同一轮内会被多次调用的工具（并行分片、循环翻页、批量入口）按单轮累计算**，不按单次。

**两条处置路径**，判据是**你改不改得了 agent loop**：

- **a. loop 侧统一落盘**（推荐）：执行循环发现返回超阈值即写文件，回给模型的是**路径 + 摘要 + 结构索引**，Agent 用读取 / 检索工具按需取用。有权改 loop / harness 时的默认选择——一处实现，覆盖现有与将来的所有工具，包括改不动的第三方 MCP。见 §二。
- **b. 工具自身兜底**：服务端过滤、分页/游标、条数上限、默认摘要 + 明细开关。只覆盖你改得到的那些工具，每加一个工具就要重做一次判断。见 §三。

走 b 的必须**建极端返回用例**（§五）：按最大规模输入实测最长返回的 token 数，落成回归用例。**实测仍 > 10k 的，停下来请用户确认是否改走路径 a。**

三条配套约束：

- **落盘不等于把信息丢掉**：返回里必须留下**导航信息**（总量、结构 / 字段概览、检索方式、文件路径），否则 Agent 拿不到它做判断所需的信息。
- **落盘的内容仍继承原始信任级别**：外部数据不因为"存成了本地文件"就变可信。
- **截断不是兜底**：直接砍掉尾部而不告知总量与获取方式，会让 Agent 拿着半截数据当全量用，比返回超长更危险。截断必须伴随"还有多少、怎么拿剩下的"。

## 一、范围与估算

**在范围内**（逐个估算，不允许抽样）：

- 本项目自建的 tools / function calling 接口
- 引入的第三方 MCP server 的每一个工具
- 自建 agent loop 里的通道工具（bash / shell / 代码执行），它们的返回同样直接进上下文

**不在范围内**（做好接口兜底即可，不必逐个建极端用例）：Skill 内的 CLI、外部 CLI。它们经 shell/bash 通道调用，由通道侧的统一截断/落盘机制兜住。但 CLI 自身仍要提供 `--limit` / 分页 / `--summary` 一类参数，且默认值取保守值——**通道兜底是防爆，不是免设计**。

**估算换算**（粗略够用，精确值以实测为准）：

| 内容形态 | 1k token 约等于 | 10k token 约等于 |
|---|---|---|
| 英文文本 / 代码 | 4KB | 40KB |
| 中文文本 | 700–800 汉字 | 1.4–1.6 万汉字 |
| JSON（字段名重复、括号多） | 2.5–3KB | 25–30KB |
| base64（图片、附件） | 750 字节原文 | 7.5KB 原文 |

估算口径三条：

1. **按最坏情况估，不按典型情况**：最大的那个仓库、最长的那条日志、最多行的那张表、最深的那棵目录树。
2. **算上重复开销**：JSON 每条记录都重复一遍字段名；返回 1000 条记录时字段名本身可能就占了一半 token。
3. **算上一轮里的多次调用**：并行调 5 次、循环调 20 次的工具，按"单轮累计"判红线，不按单次。批量入口尤其容易在这里翻车。

估不准的（返回体量取决于外部数据规模），不要写"不确定"——按 §五 构造极端用例实测，用实测值填清单。

## 二、路径 a：loop 侧统一落盘（推荐）

在 agent 执行循环里加一道统一的后处理：工具返回先量 token，超阈值就写文件，回给模型的是导航信息而非全文。

```
tool_result = call_tool(...)
if count_tokens(tool_result) > THRESHOLD:          # 建议 THRESHOLD 取 5k–10k
    path = write_to_workspace(tool_result)          # 会话隔离的工作目录
    tool_result = build_navigation_payload(         # 契约见 §四
        path=path, total=..., schema=..., how_to_query=...
    )
return tool_result
```

选它的理由：**一处实现，覆盖所有工具**——包括你改不动的第三方 MCP，以及将来才接进来的工具。路径 b 只能覆盖你亲手写的那些，每加一个工具就要重做一次判断，漏一个就是一次上下文爆掉。

四个必须一起做掉的配套：

| 配套 | 要求 |
|---|---|
| **阈值可配** | 按目标模型的上下文窗口设定，不写死。窗口小的模型要下调 |
| **落盘位置隔离** | 每个会话/任务一个工作目录，避免并发任务互相覆盖；产物可清理、可追溯 |
| **读取工具就位** | Agent 必须已被授权文件读取 + 内容检索能力，否则落盘等于把信息删了 |
| **信任级别不变** | 落盘的外部内容读回来仍按不可信输入处理，不因为"是本地文件"就当可信（见 `../safety/safety.md`） |

静默截断是明令禁止的（见 SKILL.md §绝对禁止）。落地时把"没给全"做成**结构化字段**而非一句自然语言提示：`truncated: true`、`returned/total`、`next_cursor` 或 `path`——自然语言的"（内容已截断）"会被模型当成排版噪声忽略掉，结构化字段不会。

## 三、路径 b：工具自身兜底

改不了 loop 时（用别人的 harness、接第三方 MCP）走这条。手段按优先级：

| 手段 | 做法 | 注意 |
|---|---|---|
| **服务端过滤** | 把筛选条件做成入参，在数据源侧过滤 | 最有效——数据根本不出库，胜过取回来再裁 |
| **分页 / 游标** | `limit` + `cursor`，默认值保守（如 20 条），返回里带 `has_more` 与下一页游标 | 必须告知**总数**，否则 Agent 不知道自己只看到了冰山一角 |
| **默认摘要 + 明细开关** | 默认返回结构概览与关键字段，`detail=true` 才给全文 | 摘要要能支撑 Agent 判断"要不要取明细" |
| **字段裁剪** | 只返回本工具职责必需的字段，`fields` 参数按需扩展 | JSON 里最省 token 的一刀 |
| **工具侧落盘** | 工具自己写文件，返回路径 + 导航信息（契约同 §四） | loop 改不了但工具改得动时的等效方案 |

三条硬要求：

- **上限是硬上限**，不是建议值：入参给了超大 `limit` 也要被服务端夹到上限，并在返回里说明"已按上限截取"。
- **默认值必须安全**：不传参数时的返回也不能超红线。把"不炸"寄托在调用方每次都记得传 `limit` 上，等同于没有兜底。
- **隐式规则写进工具描述**：默认返回多少条、上限是多少、怎么翻页、超限时的行为——按 `tool-design.md` §四 的「隐式规则显式化」写清，否则 Agent 会误以为拿到的是全量。

## 四、落盘返回的契约

无论落盘发生在 loop 侧还是工具侧，回给模型的载荷都要能回答四个问题：**有多少、长什么样、我要的在哪、怎么取**。缺任何一项，Agent 就只能盲目全文读回来——落盘白做，还多一次往返。

```json
{
  "status": "offloaded",
  "reason": "return exceeded 10k tokens",
  "total": {"records": 12480, "bytes": 5320000, "est_tokens": 1300000},
  "path": "/workspace/session-<id>/tool-<name>-<seq>.jsonl",
  "format": "jsonl",
  "schema": ["id", "level", "ts", "service", "message"],
  "preview": "<前 20 条 / 前 2KB 的样本>",
  "how_to_query": "按 service 过滤用内容检索工具；按时间切片直接读取指定行范围",
  "trust": "untrusted-external"
}
```

要点：

- **preview 给样本，不给结论**：让 Agent 自己判断要不要深挖，不要在这里替它总结（总结会漏、且总结本身可能被注入内容污染）。
- **how_to_query 给可执行的检索路径**，不是"你可以自己看"。Agent 拿到的是操作指令，不是安慰。
- **trust 字段随载荷传下去**：这份内容原来是什么信任级别，落盘后不变。
- 与 D1（信息完备性）冲突时，**完备性优先**——Agent 做判断必需的信息不能因为落盘而拿不到；解法是改检索方式或多留字段，不是改成"不给了"。

## 五、极端返回用例

**估算触线（>10k）或落在 5k–10k 灰区的工具必须有**，估算 <5k 的记估算值即可。走路径 a 的另测一条落盘阈值本身（确认超阈值确实触发了落盘，而不是悄悄放行）。

每条用例固定四件事：

1. **最坏输入**：能让该工具返回最多的那种输入——最大的仓库、最长时间窗的日志、无过滤条件的全量查询、最深的目录树。构造不出真实数据时用生成的等规模数据。
2. **实测 token 数**：用目标模型的分词器实测，不用字符数除以 4 糊弄；结果写进设计文档的工具返回体量表。
3. **断言**：返回 token ≤ 约定上限；且返回中带有"被截取/已落盘"的显式标识与获取剩余部分的方式。
4. **回归**：落成常驻用例。**工具改动、数据源 schema 变更、换模型都要重跑**——多返回一个字段就可能把 8k 顶到 12k。

判定与处置：

| 实测结果 | 处置 |
|---|---|
| ≤ 5k token | 通过，记录数值 |
| 5k–10k | 通过但登记为观察项，写进设计文档，下次改动重点复测 |
| > 10k | **停下来交用户裁决**：是否改走路径 a 落盘-读取。不得以"一般不会那么大"自行放行 |

### 一个完整走法（示例）

被审对象：日志查询 MCP `logs.search`，供运维 Agent 排障时调用。

1. **估算**（D4 第 2 步）：无过滤条件时返回一个服务一天的全量日志，最坏约 400MB → 按 §一 换算表（JSON 10k token ≈ 25–30KB）≈ **1.4 亿 token**。超红线四个数量级。
2. **选路径**（第 3 步）：该 MCP 是第三方的，改不了 loop（用的是别人的 harness）→ 只能走路径 b，且只能在自建的包装层里做。
3. **兜底**（§三）：包装层强制时间窗（默认 1 小时、上限 24 小时）+ level 过滤 + 500 条上限，返回带 `total`、`returned`、`next_cursor`；工具描述里写明默认值与上限。
4. **建用例**（§五）：最坏输入 = 最吵的服务 + 24 小时窗 + level=all。实测 **14.2k token** —— 仍超红线。
5. **交裁决**（D4 收尾）：停下来告诉用户"实测 14.2k，超红线 42%"，给两个选项：把条数上限降到 200，或改为工具侧落盘。用户选了落盘。
6. **改造**：包装层超 8k 即写 `.jsonl` 文件，返回 `{status: offloaded, total, path, schema, preview, how_to_query}`（§四 契约）；运维 Agent 的能力集里补上内容检索工具。
7. **回归**：极端用例断言改为"返回 ≤ 2k token 且含 path 与 total"，落进评测集；下次 schema 变更重跑。

产出写进设计文档的工具返回体量表：`logs.search | 1.4 亿（估）/ 14.2k（实测）| 触线 | 工具侧落盘 | wrapper/logs.py:offload | TC-LOG-MAX`。

## 六、常见超长源与对应压法

估算时逐条对照，这几类占了超长返回的绝大多数：

| 超长源 | 典型体量 | 压法 |
|---|---|---|
| 日志 / 监控查询 | 轻易上百万 token | 时间窗 + level 过滤 + 条数上限；原始日志落盘 |
| 数据库全量查询 | 随表增长，无上界 | 服务端 `LIMIT` + 分页；聚合结果优先于明细 |
| 目录树 / 文件清单 | 大仓库数万条 | 深度限制 + 忽略规则（`node_modules`、构建产物）+ 条数上限 |
| 全文搜索匹配 | 匹配数不可控 | 只返回命中位置 + 单行上下文，不返回整文件；命中数上限 |
| 网页抓取 / HTML | 单页数十万字符 | 提取正文、去脚本与样式；超限落盘 |
| 代码库扫描 / 静态分析 | 与仓库规模同阶 | 按模块分批；只返回结论与位置，明细落盘 |
| 批量 API 列表返回 | 字段名重复放大 2–3 倍 | 字段裁剪 + 分页；返回结构改成列式或紧凑格式 |
| 截图 / 附件 / base64 | 一张图即数千 token | 落盘给路径；确需入上下文的先压缩尺寸 |
| 子 Agent 产出回传 | 子 Agent 可能吐一整篇报告 | 在子 Agent 的输出格式里写死长度上限与结构；长报告落盘回传路径 |
| 错误堆栈 / diff | 单次数万 token | 只回关键帧 / 变更摘要，全量落盘 |

最后一条通则：**能在数据源侧减少的，不要取回来再裁**。取回来再裁只省上下文，不省延迟与成本；服务端过滤三者都省。

## 常见症状

| 症状 | 动作 |
|---|---|
| 某个工具的返回体量取决于外部数据，估不准 | 按最坏情况构造极端用例实测（§五），用实测值填清单；不接受"一般不会那么大"这类推测 |
| 上下文频繁被单次工具调用打满，但说不清是哪个工具 | 缺 D4 清单。逐个工具估算 + 实测补齐，不要靠调大上下文窗口绕过 |
| 工具自身兜底后实测仍 > 10k token | 停下来请用户确认是否改走 loop 侧落盘-读取；未获确认前不按现状交付 |
| 目标 harness 不支持超长返回自动落盘，且改不了 loop | 登记为平台缺口，在工具层实现落盘并返回路径 + 摘要 + 检索方式；第三方 MCP 改不动的，显式登记为风险交用户裁决 |
