# 可观测与回放

维度 D12。设计期定调试模式与切片契约时读；实现期建切片、排障取证据、给 D11 造夹具时也读。

**一句话**：Agentic 应用**必须内置可开启的调试模式**，把每个环节实际收到的输入与实际产出的输出留成切片，并且能只回放某一个环节——不是出了事再去补。

## 一、为什么必须内置，而不是出事再补

排障时唯一的一手证据是**当时实际发生了什么**：模型那一轮实际看到的 system 段与 messages、工具实际返回的内容、程序段实际传下去的字段。代码、提示词模板、配置、用户复述都只是**主张**（见 `../modes/debug-mode.md` §二）。

事后补记录看起来可行，实际有三个补不回来的窟窿：

| 窟窿 | 后果 |
|---|---|
| 出问题的那一次已经过去了 | 补上记录只能拿到**下一次**的证据；那一次的现场永久丢失 |
| 偶发问题复现不了 | 补了记录也等不到它再犯，只能长期挂着 |
| 补记录要改代码、发版、复现 | 从"用户报障"到"拿到第一份证据"隔着一次上线，此前的所有归因都是猜 |

所以这一维的适用条件是**全部**，不设豁免：

- 单 Agent Chat 只有一个环节，切片就是那一次调用的完整 request / response，成本极低；
- Agentic 工作流与父子 Agentic 有多个环节，切片是**唯一**能回答"哪一环开始错"的东西——错误会沿链路传播，并被下游节点的自由发挥掩盖。

**"我们有日志"不等于这一维做了。** 应用日志记的是"我们以为发生了什么"（`工具调用 0 次`、`分类成功`），切片记的是"模型收到并据以决策的是什么"。两者对不上本身就是一类高频根因。

## 二、调试模式的开关契约

**调试模式必须是运行期开关，不得是"改代码 / 重新编译 / 换分支"才能得到的东西。** 需要改代码才能观察的系统，等于没有可观测性——因为改代码这件事本身就发生在你已经需要证据之后。

四条契约：

| # | 契约 | 说明 |
|---|---|---|
| 1 | **开启不需要改代码或重启** | 配置项、环境变量、请求头、管理接口任一即可。生产上要能对**正在出问题的那类请求**定向打开 |
| 2 | **粒度至少两档：全局 + 单次请求** | 全局用于预发与压测；单次请求（按 request / 租户 / 任务类型打标）用于生产定向采样，避免为了抓一个 case 把全站切片打开 |
| 3 | **关闭态仍留骨架** | 调试模式关闭时**不是什么都不记**：每个环节的 `step_id`、类型、开始与结束时间、入出参的**体量与哈希**、状态码、错误码**必须恒开**。没有骨架，出事时连"哪一环开始错"都答不出来，也就无从决定该对哪类请求打开全量切片 |
| 4 | **开关本身受权限控制** | 全量切片含原始输入输出，打开它等于放大数据面。谁能开、开多久、开哪个租户，必须是有主的决定，并留下操作记录 |

**默认状态**：生产默认**关**（体量与隐私），预发与测试环境默认**开**。这个默认值要写进设计文档，不留给部署时临时决定。

**关闭态的骨架不是可选项**——它和全量切片是两层，不是同一件事的强弱档。骨架恒开、全量按需开，两者都要有。

## 三、切片：每个环节留什么

**切片的单位是环节，不是请求。** 一次任务产出一棵切片树：每个程序段、每个 Agent 调用、每次工具调用各是一个节点，子 Agent 展开为子树。

**每个环节至少一条切片，一条都不能少**——包括程序环节。链路里最常见的错位是程序段把数据转坏了（字段名写错、单位没换、列表被截断），而它下游的 LLM 切片看起来完全正常：模型忠实地按错误输入做了正确的事。只留 LLM 切片的系统查不出这类问题。

每条切片必须含：

| 字段组 | 内容 |
|---|---|
| **定位** | `run_id`、`step_id`、父节点 id（子 Agent 与工具调用挂在调用方下）、环节名、环节类型（程序 / Agent / 工具） |
| **输入快照** | 该环节**实际收到**的完整输入。Agent 环节 = 完整 request：system 段全文、messages 序列、tools 清单、模型 ID 与采样参数。工具环节 = 完整入参 |
| **输出快照** | 该环节**实际产出**的完整输出。Agent 环节 = 完整 response：文本、thinking、tool_calls、`stop_reason` / `finish_reason`、`usage`。工具环节 = 完整返回，含错误码与返回体量 |
| **版本三元组** | 提示词版本或哈希、模型 ID 与采样参数、代码版本。**缺这一组，切片不可回放**——比出差异也说不清是代码变了还是模型变了 |
| **判定** | 安全检查判定码、置信度、路由结论（走了哪个分支、为什么） |
| **时间** | 开始、结束、耗时 |

三条写法判据：

1. **记渲染后的事实，不记模板加变量。** "模板 + 变量"要靠一次重新渲染才能还原，而渲染逻辑本身就可能是 bug 所在；出事时你需要的是那一刻真正发出去的字节。
2. **每条切片必须能脱离上游单独反序列化成该环节的输入。** 这与 `../delivery/testing.md` §二「每个节点的输入必须能脱离上游单独构造」是同一条要求的运行期形态：做不到，说明信息传递链路定义不清——回设计文档的「信息传递链路」一节补齐，**不是把切片改成只存整链**。
3. **截断要显式标注。** 切片里的长内容做了截断的，必须留总量与获取全文的方式（同 `../tools/tool-output.md` 的落盘契约）。静默截断的切片比没有切片更糟：它看起来是完整证据。

## 四、单环节回放

**回放 = 取一条切片 → 重建那个环节的输入 → 只跑那个环节 → 与切片里的原输出比对。**

**必须支持只跑一个环节，不得要求整链重跑。** 整链重跑是"复现"不是回放，它有两个硬伤：贵；且上游只要有一点随机性，下游拿到的输入就与出事那次不同——你回放的已经不是同一个问题。

四条判据：

| # | 判据 |
|---|---|
| 1 | **副作用环节的回放必须走干跑或沙箱**。回放不得重复发送、重复扣款、重复写库、重复审批。做不到干跑的环节，回放入口默认拒绝执行并说明原因，不留"顺手就跑了"的口子（呼应 D7 幂等与 `../modes/debug-mode.md` §八）|
| 2 | **比对口径分两档**：确定性环节（程序段、或 temperature=0 且 seed 固定的模型调用）比精确值；模型环节比**结构与不变量**（字段齐全、枚举合法、条目数、引用的 ID 真实存在），语义差异交评测 Agent（见 `../delivery/testing.md` §三）。拿自然语言逐字比对的回放会天天报假差异，很快没人看 |
| 3 | **版本必须核对**：回放时的版本三元组与切片不一致的，结论**必须标注"非同版本回放"**。否则一次模型或提示词升级带来的差异，会被读成"这个 bug 偶发" |
| 4 | **回放结果本身也产出切片**，与原切片可并排比较。排障要的是 diff，不是两份要人肉对照的长文本 |

## 五、脱敏、留存与体量

切片含原始输入，等于把系统里流过的所有数据又存了一份。三条硬要求：

- **写入时脱敏，不是读取时脱敏。** 凭证与密钥一律不落盘（`Authorization` 头、API key、token 一律替换为占位）；PII 按 D8 的规则处理。事后再去洗一遍已落盘的切片，成本高且必然漏。
- **必须定留存期**，并按环境分档（生产短、预发长）。无限期留存不可接受——它把一个可观测性设施变成了一个越来越大的数据泄露面。被固化成回归夹具的切片是例外，但那份**必须先脱敏再入库**（见 `memory.md` §七 日志与遥测的脱敏）。
- **切片落盘、落对象存储，不进模型上下文。** 全量切片的体量与 D4 同阶甚至更大；读切片时按 `../modes/debug-mode.md` §三 先降噪成骨架时间线，需要哪一段再按 id 取。

**切片读回来仍是不可信内容**，信任级别继承落盘前的来源（见 `../safety/safety.md`）——它里面本来就装着用户输入、网页正文、第三方 API 返回。尤其在把切片当夹具喂进回归用例、或喂给评测 Agent 时，不要因为"这是我们自己存的文件"就当可信。

## 六、与其它维度的接缝

| 维度 | 接缝 |
|---|---|
| **D11 测试与评测** | 切片是夹具的**首选来源**。`../delivery/testing.md` §二 要求每个节点有典型 / 边界 / 异常三类输入，这三类**优先从真实切片里挑**，手工构造只用来补真实流量覆盖不到的维度。修过的每个缺陷，把触发它的那条切片固化成回归样本 |
| **排障** | `../modes/debug-mode.md` §二 的"第一动作是拿到对话记录"，在 D12 做到位的系统里就是"取那次 `run_id` 的切片"。取不到 = D12 没做 = **架构缺陷**，按 P0 单独置顶，而不是就地补一段日志了事 |
| **D8 记忆与隐私** | 切片属于「轨迹」这一类状态，与用户记忆分开存；**不得被检索层当作知识召回**——试错过程被当成事实，正是记忆污染最常见的来源 |
| **D9 成本与性能** | 开启全量切片会增加存储与写入开销，这笔成本记进 D9 预算；生产默认关、定向采样正是为此 |
| **D7 可靠性** | 恢复用的检查点与切片是两回事：检查点为了**继续跑**，切片为了**看清楚**。可以共用存储，但不要用检查点顶替切片——检查点只存继续执行所需的最小状态，缺输入全文 |

## 常见症状

| 症状 | 动作 |
|---|---|
| 出了问题只能靠"加点日志再跑一次" | D12 没做。按 §二 补调试模式与骨架，不要一次次改代码换取一次次观察 |
| 有 LLM 调用日志，但记的是提示词模板与变量 | 换成渲染后的实际 request（§三 判据 1）。模板对不出真相 |
| 只留了末端产物快照，中间环节没有 | 按 §三 补每环节切片，含程序环节。只有末端快照时，末端正确不代表中间没坏 |
| 要回放只能整链重跑 | 环节输入不能独立重建，是信息传递链路定义不清，回设计文档补（§三 判据 2）|
| 回放把生产的通知又发了一遍 | 副作用环节必须干跑或沙箱，且默认拒绝执行（§四 判据 1）|
| 回放天天报差异，团队已经不看了 | 多半在拿自然语言逐字比对。改成结构与不变量断言 + 评测 Agent（§四 判据 2）|
| 切片里翻出明文 token | 先吊销该凭证，再改成写入时脱敏（§五）；已落盘的历史切片一并清理 |
| 生产切片存了两年没人删 | 定留存期并落实到清理任务（§五）。这已经不是可观测性设施，是数据泄露面 |
